# Prospective workload-momentum comparison

Candidate: workload_momentum_v1 (RoleFeatures without teammate competition). Baseline: the unchanged production FactorModel. Identical training observations, estimator settings and current roster fixtures; only feature construction differs. The candidate adds last observed workload and its difference from the preceding three observed games. Never use it to change production rankings, lineup choices or FAAB bids during this study.

Collection starts now. Formal evaluation window: 2026 regular-season weeks 9–17, selected before those outcomes. Week 8 is an operational preview because an earlier baseline-only archive already exists. Earliest retained capture per league/roster/week is selected without inspecting results, including Tuesday or dry-run captures. If that capture lacks candidate predictions, the week is missing; do not substitute a more favorable later run. Require at least eight paired weeks; otherwise report insufficient prospective evidence and preregister a new window before collecting more outcomes.

Primary endpoint: candidate-minus-baseline absolute error on the same pregame, rostered offensive players with observed completed-game outcomes. Exclude late captures and unresolved outcomes; do not impute DNPs. Store weekly count and absolute-error sums for paired block-bootstrap analysis at the end of the window (two-week blocks, one/three-week sensitivity). Report effect sizes, intervals, positional diagnostics and missing coverage. There is no automatic 2% rejection and no automatic promotion based on a p-value. Nine weeks and a single roster will still limit inference.

The existing private scorecard pipeline computes descriptive paired weekly totals, but significance and promotion are reviewed only after the window closes. Actual lineup-decision benefit is a separate future endpoint: no claim of a decision advantage will be made from point-error improvement alone. Do not tune or add candidates mid-window.

Snap sources are fetched with timestamps and hashes, joined by PFR/GSIS IDs and strictly filtered before the forecast period. Require at least 95% snap coverage in each training season. Save the enriched training frame and both forecasts with hashes in the private evidence archive; capture time controls pregame eligibility. Unknown/failed research inputs produce an unavailable shadow status and leave the established report operational. All source/model provenance is retained. Future protocol changes require a new candidate/protocol version.

## Private collection monitor

Each successful private archive update writes an immutable `studies/workload_momentum_v1/<league-roster-hash>/<outcome-archive-hash>.json` summary. It uses the same earliest-capture selection as scorecards; a missing candidate is never replaced by a later run. Every protocol week is visible, including missing captures, missing candidates and awaiting outcomes. Descriptive error totals use identical paired rows, aggregate by observation count rather than averaging weekly MAEs, and include positional diagnostics when recorded.

Before the week-17 window closes, status remains `collecting`. Afterward, at least eight scored paired weeks yields `ready_for_final_analysis`; fewer yields `insufficient_paired_weeks`. Readiness is a data-count check, not statistical significance or a recommendation to promote. A week with some paired observations may still have unresolved players: final review must examine the per-week coverage before inference. The final block bootstrap remains a separate preregistered analysis. These private summaries contain no p-values, interim confidence intervals or automated promotion decisions. New outcomes may resolve more observations; each summary retains the outcome archive hash so revisions are auditable.
